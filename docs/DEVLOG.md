# Dev Log

## 2026-05-08 — production deploy prep

- **upload-studio/package.json** and **TypeScript config**: Restored the missing Vite build metadata so the Upload Studio frontend can install and build on a server. This was a deployment blocker because `npm install`/`npm run build` had no package manifest to use.
- **upload-studio manifest cleanup**: Fixed malformed concatenated `package.json`/`tsconfig` contents found during `npm install` and `npm run build`; the frontend now has single valid JSON config files.
- **.gitignore**: Added local database backups and uploaded clip storage to the ignore list so deployment commits do not push runtime media or SQLite artifacts. Added narrow exceptions for Upload Studio package and TypeScript config JSON files because the existing broad `*.json` secret guard hid required build metadata from Git.
- **Upload-only cleanup**: Removed appended stale legacy workflow docs from the auth guide, scripts guide, rebuild spec, and env template. Simplified `ConfigManager` and `VideoProcessor` so Python runtime helpers only cover web-upload settings, platform upload optimization, and publishing validation.
- **Production deploy**: Pushed the upload-only app to `jamie-legg/AIOCC`, deployed `/data/syn.gl/aiocc` on `syn-uk`, installed project Python via `uv`, built the Vite frontend, added `aiocc-upload.service` on port `8010`, and configured nginx/Let's Encrypt for `https://upload.syn.gl`. Public `/health` and `/api/v1/studio/status` are reachable; OAuth tokens were not present on the host, so platform cards currently show re-auth required.
- **Public repo hardening**: Untracked local SQLite/database and generated media artifacts, expanded `.gitignore` for tokens/databases/uploads/screenshots, added `SECURITY.md`, and replaced realistic-looking secret placeholders in Kubernetes examples.
- **OAuth guide**: Expanded `docs/authentication/AUTHENTICATION_GUIDE.md` with provider-specific authorized redirect URIs for YouTube, Instagram, and TikTok.
- **Hosted OAuth and UI privacy**: Replaced the platform-card local helper launch with hosted OAuth URLs and FastAPI callbacks at `/api/oauth/{platform}/callback`. Removed server log paths, `.env` variable names, raw backend failure details, and absolute deployment paths from public UI/API responses; Upload Studio now shows generic connection/action messages while details stay in server logs.
- **Production OAuth redirect override**: Fixed the `syn-uk` private environment after verification showed Instagram still using an old ngrok redirect override. YouTube, Instagram, and TikTok production redirect variables now point to `https://upload.syn.gl/api/oauth/{platform}/callback`.
- **Public history rewrite**: Replaced the newly published GitHub history with a clean public root commit so removed local databases, screenshots, overlays, and test media are no longer present in branch history.
- **JWT RBAC**: Replaced the temporary studio token gate with username/password login, JWT bearer auth, and `admin` / `creator` / `viewer` roles. Added bootstrap admin support, admin user creation, per-user upload history filtering, and an admin monitoring panel for user/upload counts.
- **Password hashing**: Switched auth hashing to `pbkdf2_sha256` after production bootstrap hit bcrypt backend/version limits with generated credentials.
- **auth.syn.gl SSO**: Repaired the existing `/data/auth` OAuth service on `syn-uk`, rotated its default admin password/secrets, registered Upload Studio as an OAuth client, issued a valid `auth.syn.gl` certificate, and added Upload Studio SSO start/callback routes while keeping local login as a fallback.
- **auth-syn-gl module tracking**: Added `auth-syn-gl/` as an open-source module scaffold with secure env template, package metadata, data model draft, OAuth client registry, and phased upgrade roadmap for shared syn.gl identity, roles, AI usage, and monetisation.

- **upload-studio/**: Added a fresh Vite/React/Tailwind app that closely follows the supplied screenshot: connected platform cards, drag-and-drop clip input, clip preview, platform picker, AI metadata editor, visibility control, upload CTA, and recent uploads. It uses `/api/v1/studio/*` with local fallback data for UI work when the backend is offline.
- **backend/src/api/studio.py**, **backend/src/models/studio.py**, and **backend/src/main.py**: Replaced the old edited-video save endpoint with a flat-file upload API, metadata generation endpoint, recent uploads endpoint, minimal `UploadedClip` / `PlatformUpload` models, and static serving for stored uploads.
- **Cleanup**: Removed the legacy local automation stack, legacy `src/analytics` API, old dashboard, obsolete docs, and stale utility scripts.
- **Docs/config**: Updated `docs/README.md`, getting-started docs, backend docs, `env.example`, `Makefile`, `pyproject.toml`, lockfiles, and start/setup scripts for the simplified Upload Studio stack. `docs/INDEX.md` is still absent, so `docs/README.md` remains the docs hub.
- **scripts/start_all.py**: Fixed Windows startup by resolving `npm.cmd` before launching the Vite upload studio. Initial run failed with `FileNotFoundError` when Python tried to spawn `npm` directly.
- **upload-studio/src** and **backend/src/api/studio.py**: Removed screenshot mock identity/content from runtime fallbacks. Status now derives connected state from existing `.env` upload/OAuth settings, frontend fallbacks are neutral, and placeholder Warzone upload rows from the mock run were deleted.
- **src/managers**, **src/platform_uploaders**, and **backend/src/api/studio.py**: Restored the real OAuth/upload stack that had been removed too aggressively. Studio upload now calls the existing `UploadManager.upload_to_all_platforms()` path instead of a local-save stub, and platform cards are based on actual OAuth credentials.
- **OAuth re-auth**: Added `scripts/auth_platform.py` and `/api/v1/studio/auth/{platform}/start`; clicking a top platform card starts the existing OAuth sequence and opens the browser flow. YouTube now loads the legacy `~/.content_creation/youtube_token.json`; the current token is expired and cannot refresh with the `web` client in `creds/` (`unauthorized_client`), so it needs re-auth. Instagram is expired/invalidated by Meta and also needs re-auth. TikTok resolves to `syn`.
- **OAuth redirects**: Fixed Instagram/TikTok re-auth to use `INSTAGRAM_REDIRECT_URI` / `TIKTOK_REDIRECT_URI` from `.env` instead of generating `/callback`. The local callback server now accepts `/api/oauth/.../callback` paths through the ngrok tunnel, matching the registered redirect URI and avoiding Instagram `invalid_redirect_uri`.
- **YouTube OAuth launch**: Auth subprocesses now log to `~/.content_creation/auth_<platform>.log` instead of discarding output. YouTube card-click auth now forces a fresh browser authorization instead of silently reusing the expired `youtube_token.json`.
- **YouTube browser fallback**: Auth helpers now run unbuffered so Google’s fallback authorization URL is written immediately to `~/.content_creation/auth_youtube.log` when Windows does not open the browser automatically.
- **YouTube redirect**: Switched YouTube re-auth for the web OAuth client from `run_local_server()` localhost redirects to the registered ngrok callback `OAUTH_REDIRECT_BASE_URL/api/oauth/youtube/callback`. Verified that callback is present in `creds/client_secret_...json`.
- **YouTube token expiry**: Fixed Google OAuth expiry parsing by treating naive `youtube_token.json` expiry timestamps as UTC. The token created by the ngrok callback was valid, but local timezone interpretation made it look expired; dashboard status now shows YouTube connected as `syn`.
- **Instagram upload failure**: The latest Instagram pass failed after Graph container creation because the hosted video URL used `https://ftp.syn.gl/...` and the public certificate is expired. The uploader now fails before container creation with a clear SSL/public-hosting error and no longer prints token-bearing media/status URLs in debug logs.
- **ftp.syn.gl certificate**: Renewed the expired Let's Encrypt certificate on `syn-uk` for `ftp.syn.gl`, reloaded nginx, and verified the hosted video URL now returns `200` over valid HTTPS. Instagram should now be able to fetch newly uploaded hosted videos.
- **Upload retry UI**: Added `/api/v1/studio/uploads/{upload_id}/retry` backed by the real `UploadManager` and added Retry controls for failed rows in Recent Uploads. The existing failed Instagram row can now be retried from the dashboard after the `ftp.syn.gl` certificate fix.
- **nginx production cleanup**: Removed the duplicate `ftp.syn.gl` port-80 server block from `ftp-minio`, reloaded nginx, and confirmed the duplicate server-name warning is gone.
- **Instagram hosted object metadata**: The retry still failed after SSL was fixed because MinIO served uploaded MP4s as `binary/octet-stream`. `FTPUploader` now sets `ContentType` from the file extension (`video/mp4` for MP4) and cache metadata on upload, so the next retry creates an Instagram-fetchable object.
- **Instagram retry regression check**: Git history shows the previously working Instagram upload path used a 60fps / 8 Mbps Instagram upload copy. Restored that historical Instagram-specific output while leaving the source/master clip untouched at 120fps. Hosting fixes remain in place: valid HTTPS cert and `video/mp4` object metadata.
- **Instagram robots.txt blocker**: Probed the failed Graph media container with `error_message` and found Meta was refusing the hosted video because `ftp.syn.gl` was restricted by `robots.txt`. Updated nginx on `syn-uk` so `https://ftp.syn.gl/robots.txt` explicitly allows `/ftp-files/` and `/`.
- **Instagram media host**: Meta continued reporting the cached `ftp.syn.gl` robots restriction. Added a clean `/ftp-files/` proxy and permissive robots response on `api.uk.syn.gl`, then changed `FTPUploader` public URLs to default to `https://api.uk.syn.gl`. New retries should avoid the cached `ftp.syn.gl` robots decision.
- **Upload Studio spacing**: Added padding to the left upload panel, AI metadata card, recent uploads card, and platform picker to remove edge-hugging cards in both columns.
